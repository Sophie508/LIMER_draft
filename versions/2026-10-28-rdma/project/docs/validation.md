# 独立工程的验证

本项目的验证分为两部分，不能混为同一批实验。

当前独立工程有 20 项 Python 检查：13 项原逻辑/代理审计与指标正反例、4 项配置边界与可移植输入检查、3 项构建描述和传输库完整性检查；Windows 和本项目 Docker 镜像中均通过。

## 原验证参考

`reference/closed-loop-20261027.zip` 保留原工程 53 次运行的完整导出证据（7 项资格、40 项主对照、6 项边界），文件未改写。`python limer.py verify-reference` 核对 1,388 个导出文件、源码/工具冻结记录和全部 53 次结果。该数据包用于证明原结果与来源一致，不声称这是重构后重新跑完的 53 次。

## 本次独立构建和回归

新容器只挂载本项目源码和新建的构建卷，没有挂载原项目或旧构建卷。底层库和应用均由新工程内的固定源码编译，没有读取旧目标文件或旧链接命令。移除 AstraSim 应用入口后，由自有网络初始化创建拓扑和 RDMA，独立应用名为 `LimerSimulator`。

7 个回归案例全部重新执行并通过独立物理/逻辑审计、逐包 M13 重放和压缩档内容核验：

每个案例还比较 12 类原始日志的 SHA256：逻辑事件、逐包接纳/接收、线上流量、观测、代理资源、QP 分段、控制、阶段、检测、M13 告警/基线与故障事件。7×12=84 项全部逐字节一致；全部状态字段和输入方法/场景也一致。这验证的是这些固定输入下模型行为保持，不能据此声称所有可能场景都已穷尽。

构建和回归的实际证据在 `validation/build.json`、`validation/regression.json`、`validation/results.json` 和 `validation/runs/`。新原始大日志压缩档保留在新构建卷的 `/work/qualification-v1/archives/`，本交付保存逐文件哈希及紧凑核验记录。

## 进一步工作

当前模型仍有已知局限：纯容量下降不一定被 M13 识别；代理空闲条件、最终通知、无可用代理、计算与 HBM 开销尚需后续研究。本次交付重构保留原模型，不通过修改阈值或隐藏失败来制造性能收益。
